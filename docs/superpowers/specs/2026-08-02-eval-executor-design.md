# Increment 2b — EvalExecutor (`looprun-eval campaign`)

Date: 2026-08-02 · Status: CLOSED — shipped. `runCampaign` lives in `packages/eval/src/campaign.ts`.
· Repo: looprun · Depends on: increment 2a (validate, judge-input, fold-sync)

## Problem

The Atlas measurement was hand-orchestrated: ~30 bash invocations, improvised `until … sleep`
watchers, background agents, and six "how's it going?" nudges from the user. Measured incidents:
a rep overwrote `r0`; `.env.local` not loaded produced a 178-error round; out-dir clobbering;
the monitor armed only after the user complained; the certification floor first reported from a
hand computation that no instrument produced. Orchestration is deterministic work — engine work.

## Deliverable — one verb, whole campaign

```jsonc
// campaign.json (generated by the skill at TEST time)
{ "subject": ".", "reps": 3, "control": "ungoverned",
  "perturbation": "user-tail",              // inert per-rep perturbation for deterministic decodes
  "bar": 0.9, "chunk": 10,
  "out": "test/2026-08-02-campaign" }
```

`looprun-eval campaign run campaign.json` executes:

1. **Preflight** — `validate` green; env keys present (fail BEFORE spending tokens: the
   178-error round becomes a preflight refusal); out dirs empty or `--resume`.
2. **Runs** — K governed reps + control, each in its own immutable dir (`r0/ r1/ r2/ control/`);
   a finished dir is never overwritten (resume skips completed reps).
3. **Monitor always armed** — NETWORK + HOLES vigils on every run dir (FINGERPRINT/SPEED when the
   target is local); MONITOR.md written per dir; the campaign refuses to certify over unresolved
   incidents.
4. **Judge inputs** — `judge-input --chunk` per run dir, blind. The campaign then PAUSES with a
   machine-readable manifest (`judging.json`: input paths, expected verdict counts) for the host
   to dispatch judge subagents per the agentspec protocol. `campaign resume` continues when
   verdict files are complete.
5. **Fold + sync + range** — fold per rep, byte-identical verdict sync across dirs, then
   `cert r0 r1 r2` (FLOOR law). Numbers exist ONLY as instrument output.
6. **Status** — `campaign status` prints per-phase progress (cases run / verdicts written /
   incidents) so the operator, or an active watcher, polls ONE command instead of improvising.

## Laws encoded

- No hand-computed figures: the campaign's report quotes `cert-range.json` verbatim.
- A rep dir is append-only after DONE; re-measurement is a NEW campaign dir (dated), old dirs are
  history.
- Judge model/tier is the host's strongest available (recorded into the manifest for the record);
  the campaign records which model judged each rep.
- Control variant always runs (the A/B is part of the instrument, not an option).

## Testing

- Scripted-model campaign end-to-end in CI (no network): preflight → runs → manifest → fake
  verdicts → fold/sync/range; asserts immutability (second run refuses), resume, and that the
  range file is the only number source.
- Preflight failure fixtures: missing env key; dirty out dir; validate red.
- Monitor gate: a seeded network-incident log blocks cert until marked resolved.

## Out of scope

Judge execution itself (host subagent, agentspec protocol); world DSL; multi-target matrices
(a campaign is one target — stage-2 model sweeps are N campaigns).
