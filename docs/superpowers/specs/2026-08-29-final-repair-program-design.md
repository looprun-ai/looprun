# The Final Repair Program — Every Known Class to Zero, Then One Certification

**Status:** DRAFT — pending owner review
**Program:** `2026-08-28-natural-voice-recovery-design.md` — this plan REPLACES the
bare "F5 then F2" tail with a de-risked sequence: R1 (engine repairs, each
micro-tested) → F5 (declaration laws + exam repairs + pages, each with its slice) →
F2 (certification, not discovery).
**The rule that shapes it:** no step scales until its mechanism is proven on a cheap
micro-test, and no full run happens while any known class is unrepaired. F2 is the
LAST run, and it certifies — it does not discover.

## 2 · Two mechanisms already proven at zero cost (recorded data, no model calls)

**The prose-gate catches the read-content class.** Over the photo's own recorded
dumps: 82 replies were delivered without the composing call; the gate — "a done read
returned record identifiers and the reply carries none of them" — flags exactly 7.
Three are the real fails (30, 71, 83 — it caught 83 before the human read did: the
reply promises "the three most recent actions are listed below" and lists nothing).
Four are true-negative answers ("no holds standing") whose flag is harmless: the
consequence of a flag is ONE composing call with the read material — a call that can
only ground the reply further. Cost of false flags: ~4 calls per 100 cases.

**The two-outcomes fact was clean.** Route-78's stored fact reads "Money recorded
here is money the customer is treated as having sent" with the held tag — the
composing step itself added "so I have recorded the payment … as requested". The fix
is a template rule, not new machinery.

## 3 · R1 — the engine repairs (three edits, one directed slice)

| edit | where | the change |
|---|---|---|
| R1a | `reply-composer.ts` closed-world lines | speak only of what was not DONE this turn; never state that a record does not exist or is absent — only a read's own result can say a record is missing |
| R1b | `turn.ts` no-call delivery path | the proven prose-gate: done-read ids absent from the reply → spend ONE composing call with the read material; otherwise deliver as today |
| R1c | `reply-composer.ts` rules | "as requested" never turns a held act into a done one — a held act is never described as performed |

Validation, in order:
1. unit fixtures for the gate (zero calls) + whole suite green;
2. the recorded-dump gate script re-run over the photo's dumps stays at 7 flags;
3. ONE live directed slice — {02, 64, 30, 71, 83, 78} must flip green, {60, 49, 95}
   must stay green (true not-found, honest not-processed, true no-holds — the
   guards against over-repair). ~9 cases. Every letter read in session.
A red case → adjust the single edit that owns it, re-run the slice. No other work
starts until the slice is green.

## 6 · What this plan guarantees, and what it cannot

Guaranteed: **zero cases failing for a cause we know** — every deterministic class
in §1 lands with its own green slice before F2 spends anything, and a class that
re-appears trips the stop-and-repair protocol instead of another full run.

Not guaranteed, said plainly: the subject model is stochastic. The photo itself
shows the same question answered fully in one case and emptily in its twin, and one
booking opened on the wrong machine while its twin run chose right (72, 76). That
variance band — ~2–4 cases per 100, symmetric with the baseline's own flaps — no
rule can promise away. The honest expectation for F2 is ≥95 with every failure
either variance-class or a NEW discovery that stops the line.
