# What an author who had read only the skill could not do

An agent read the agentspec skill's pages and nothing else, then authored the Atlas subject. It
returned these as the places the pages left it guessing. Two were defects in the static gate and
are fixed; the rest stand.

## Fixed

| # | the gap |
|---|---|
| A | the pairing lint read the tool surface from the SOURCE, and this world card builds its three effect blocks with `Object.fromEntries` — so it saw zero tools and every declared act came back as unknown |
| B | a guard object literal carrying both `name:` and `rule:` over a spread factory was read as a prose rule, so the catalog's own "sharpen the rule" pattern produced 26 findings |

## Four shapes the ladder has no rung for

```
  a capability that depends on an ARGUMENT      resolveClaim: money capability on approve, not on deny
  a value from the operator OR from a record    the settlement figure
  an argument compared against a RECORD         never transfer to this same workspace
  a read owed unless already read this turn     checkAvailability against the account
```

## What the surface interview could not reach

gen.md's interview table says to walk "each `gates` entry on a world card". This world card has
**no `gates` at all** — every condition is a `fail(CODE)` inside a custom executor. The author
walked the handlers instead and said so; the page does not tell you to.

The same world card carries roughly 35 bare refusal codes and only five refusals with a `detail`.
Lesson 12 states that every refusal a held call can hit is a sentence somebody reads. On this
surface that is false, and `world.ts` is ported data the author may not touch.
