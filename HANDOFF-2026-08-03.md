## 5. Breaking changes an integrator must know

- `did` is MANDATORY (`minItems:1`, enforced at the tool boundary AND in `validateClaims`); `asked` is gone.
- `finalizeReply` with `did: []` EXHAUSTS (declaration floor).
- `didMessageConsistency` defaults `failMode:'closed'` (bare `llmCheck` stays `'open'`).
- `exhaustionReply` supplies the closing SENTENCE only — the engine always prepends the derived report.
- A domain's write result must name what it touched under an IDENTITY KEY, as a whole value
  (no tokenizer). Numeric ids only count under an identity key. Reads name their subject in an
  identity-key ARG. `GUARDS.md` carries the full obligation table.
- **The mastra json-schema→zod converter used to drop `description`/`minLength`/`minItems`** — the D4 op
  prose never reached the model. Fixed; the carried-keyword set is now a decided, test-pinned contract
  (`packages/mastra/src/json-schema-zod.ts`). Consequence: model-facing tool-schema bytes changed for
  every subject, so pre-MI benchmark runs are NOT comparable (noted in `docs/benchmarks.md` §3).
